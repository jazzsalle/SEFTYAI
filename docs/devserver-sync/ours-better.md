# SEFTYAI가 더 나은 점 — 개발서버 역반영 검토용

개발서버를 복제하면서도 지우지 않고 유지하는 기능이다. 개발서버에 반영할지는 담당자가 판단한다.
각 항목에 「개발서버 반영 시 참고」를 적는다. 경로는 `app/src/` 기준.

## 1. 연락망·상황전파
- 비상연락망 조직도, 조직·담당자 편집, 전파그룹, 엑셀 내려받기·올리기 (`components/contacts/*`, `/contacts`)
- 대응절차 탭에서 상황전파 문자·이메일 초안 → 발송, 2분 안 같은 내용 재발송 확인, 발송 결과 5초 갱신·실패자만 재발송 (`PropagateModal.tsx`, `DispatchHistory.tsx`, `/api/dispatch*`)
- 개발서버 반영 시 참고: 개발서버에는 연락망 화면이 없다. 표 `sa_contact_*`, `sa_dispatch*` 구조를 옮기면 된다. 발송 모듈은 지금 모의(mock).

## 2. 대응절차 수정본·지난 상황 보관
- 행동카드 수정본을 기관 공용으로 저장, 원문 되돌리기, 내보내기·가져오기 (`SopEdit.tsx`)
- 「새 상황으로 시작」 시 체크를 지난 상황으로 보관, 30일 뒤 삭제 (`/api/checks/history`)
- 기준지역이 소속과 다를 때 「우리 기관 매뉴얼」 안내 띠 (`SopPane.tsx`)
- 개발서버 반영 시 참고: 개발서버 `manual/poc/*`는 SEFTYAI 화면을 가져간 것이라 수정본·보관 기능만 더하면 된다.

## 3. 답 받기 방식
- STREAM(SSE)으로 글자 단위로 이어 받고, 끊기면 폴링으로 이어 받음 (`lib/session.tsx`, `/api/agent/jobs/[id]/stream`)
- 개발서버 반영 시 참고: 개발서버는 EventSource에 인증 헤더를 못 실어 폴링만 쓴다. SEFTYAI는 쿠키 세션이라 가능. 개발서버는 쿼리 토큰이나 fetch 스트림 읽기로 풀 수 있다.

## 4. 답 재사용 규칙
- 열쇠: 질문 글·출처·조건(정렬)·특보 성분·참조·이어 묻기 대화·AI 모드 10분 구간 (`lib/server/jobs.ts` `cacheKeyOf`)
- 24시간 재사용하되, 1시간 넘은 답은 그 지역에 특보가 발효 중이면 다시 받음
- 같은 열쇠가 진행 중이면 그 작업에 합류(중복 호출 방지), 3초 안 같은 글 재전송 차단
- 답 받은 때의 특보를 기록해 「답을 받은 뒤 특보」 주의 표시
- 개발서버 반영 시 참고: 개발서버는 첫 턴만, 기간을 정시로 깎은 키로 캐시한다. 특보 발효 시 단축 규칙과 진행 중 합류가 없다.

## 5. 동시 실행 한도·작업 관리
- 계정당 4건·전체 8건 한도를 잠금 한 번으로 계산, 15분 시간 초과 시 T3Q 취소, T3Q가 작업을 잃으면 90초 안 1회 재제출, 방치 작업 거두기 (`jobs.ts`)

## 6. 운영관리 화면
- 질의 현황(강제 취소·원응답), 브리핑 예열, 시연 세트 예열(시연 시나리오 특보 켜기·끄기), 계정 잠금 해제, 답변 평가 모아 보기, 추적로그 (`app/(main)/admin/page.tsx`)

## 7. 시연 지원
- 시연 고정 답(항목별 성공 답 고정, 새로 받는 중인 답이 성공하면 교체) (`demoPins`)
- 시연 시나리오 가상 특보: 시연 계정 3개만 기상청 대신 고정 특보, 화면에 「실시간 특보 끊음」 표시 (`lib/server/scenario.ts`)
- 「시연 자료」 미리 만든 인포그래픽 (`DemoInfographic.tsx`)

## 8. 그 밖
- 인쇄용 대화 보고서 (`/report`)
- 대화 저장 전 주민번호·휴대전화·이메일 가리기, 운영자가 남의 질문을 볼 때 개인정보 가림 (`convStore.ts`)
- 도움말 검색·예시 질문 바로 보내기 (`HelpCenter.tsx`)
- 지도 범례 카드·말풍선(답에서 보기·가까이 보기·같은 종류만) (`MapLegendPanel.tsx`, `MapPopup.tsx`) — 개발서버 `map/poc/MapLegendPanel.tsx`는 이것을 가져간 것

## 9. 1차 보완(2026-11-06)에서 남긴 것
- 받지 못한 답(응답 상태가 SUCCESS가 아님)에도 [원문 보기]·[마크다운 원문 복사]를 둔다 — 일부 제공으로 온 글을 담당자가 직접 확인할 길이 남는다 (`components/answer/AnswerCard.tsx`)
- SUCCESS가 아닌 답은 24시간 재사용·시연 고정 대상에서 뺀다 — 실패로 보이는 답이 다음 질문에 다시 붙지 않게 (`lib/server/jobs.ts`)
- 특보 띠가 돌아가는 동안에도 [모두 보기]로 발효 특보 전체를 한 번에 본다, [정지] 단추는 좁은 화면에서도 남는다 (`components/AppShell.tsx` `WxBar`)
- 개발서버 반영 시 참고: 개발서버 `AnswerPanel` 실패 알럿에 원문 보기를 붙이려면 `turn.envelope`가 이미 있으니 그대로 쓰면 된다. 캐시는 백엔드 `AgentJobs` 재사용 조건에 상태 SUCCESS를 거는 것으로 같다.

## 10. 스타일 구조
- KRDS 원본 CSS를 싣지 않고 토큰만 `app/globals.css` `:root`에 둔다(변수 이름은 개발서버 `styles/renewal/tokens.css`와 같다). 화면별 스타일은 컴포넌트 옆 `.css` 한 곳에만 둔다.
- 개발서버는 `krds.min.css`(1rem=10px) → `index.css`(7천 줄) → `styles/renewal/*`(같은 클래스를 덮음) 세 겹이라, 한 요소에 규칙이 두세 번 걸리고 읽는 순서가 바뀌면 화면이 깨진다.
- 개발서버 반영 시 참고: renewal 덮어쓰기는 그대로 두되, renewal이 이미 덮은 `index.css` 규칙을 한 번 걷어내면 고칠 곳이 하나로 준다. 개발서버 치수(rem, 1rem=10px)를 옮길 때는 ×10 px로 바꾼다.

## 11. 질문 모음 맞추기(2026-11-06)에서 남긴 것
- 받아 둔 답의 짝을 ID 하나로만 찾는다(개발서버는 ID + 질문 글) — 대신 질문 글은 코드(`lib/library.ts`)에만 있어 서버 시드와 어긋날 일이 없다. 가져오기 도구는 개발서버처럼 글까지 같을 때만 넣는다 (`harness/demo/import_pins.mjs`)
- 「받는 중」은 서버 작업 상태(QUEUED·SUBMITTED·RUNNING)로 본다 — 브라우저를 닫았다 열어도 받는 중이 보이고, 끝나면 5초 안에 고정 답으로 올라간다. 개발서버는 이 화면이 받는 중인 것만 알아 RUNNING 이 굳는 일이 있었다(11/4) (`lib/server/jobs.ts` `demoPins`)
- 「지역 질문」 체크박스에 고르는 질문 글을 보조기기 이름으로 붙인다 (`components/explore/LibraryDrawer.tsx`)
- 개발서버 반영 시 참고: 개발서버 서버 시드 주석은 한눈 요약 질의를 「마흔한 개」라 적었으나 실제 항목은 47개(묶음 3~5)다.
