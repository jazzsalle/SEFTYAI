## 5. `작성가이드` 시트 (원문)

- [기능분해도] 작성 가이드
- 작성법
- 요구사항정의서를 기반으로 요구사항 단위로 업무기능, 업무프로세스, 단위프로세스(기능)를 정의한다.
- 1. 작성자 : 업무 분석담당자
- 2. 작성항목 : — * L1 : 100000 — 업무기능을 식별하기 위한 ID 체계를 앞에 2자리로 식별한다. 1~10까지 정의한다.
- * L2 : 101000 — 업무프로세스을 식별하기 위한 ID 체계를 앞에 2자리로 식별한다. 1~10까지 정의한다.
- * L3 : 101000 — 단위프로세스 기능을 식별하기 위한 ID 체계를 앞에 2자리로 식별한다. 1~10까지 정의한다.
- # 추후 요구사항 vs 단위프로세 추적을 위해 ID 체계는 임의로 조정할 수 없다. 단 대규모 시스템의 경우 아이디 자릿수 변경이 가능하며 PMO와 협의하여 포맷을 변경한다.
- * 업무기능 명 : 기업의 임무를 한층 더 멀리 조명하여 하나로 표현하는 완벽한 단위 업무기능의 그룹.
- 일반적으로 최상위 업무 기준의 기능 분해의 예가 됨(영업, 회계, 제조 등)
- * 업무프로세스 명 :  입력과 출력이 존재하는 업무기능으로 프로세스를 실행함으로써 데이터의 입력과 출력이 수행됨
- 업무 프로세스 판단 근거
- ① 해당 업무 기능이 실행 단위인지 관리 단위인지 판단
- ② 업무기능에 입력과 출력의 행위가 이루어지는지를 확인
- * 단위프로세스 명 : 일반적인 기능 단위를 의미하며 데이터 관점에서는 엔티티 단위로 추가,수정,삭제, 조회와 같이 단위 업무
- * 요구사항 ID : 요구사항정의서에 명시된 아이디
- * 요구사항 명 : 요구사항정의서에 명시된 요구사항 명칭
- * 연동 구분 유형 — - API : 백엔드 API 호출
- - Function : 내부 단독 함수 호출
- - SignalR : SignalR 통신 (REST API 없음)
- - External : 타 백엔드 서비스 제공 (REST API 없음)
- - UI : 화면 단독 처리
- - None : 그 외 비고란에 작성
