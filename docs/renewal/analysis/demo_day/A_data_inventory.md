## 0. 조사 방법

- 지역당 30회 안쪽 · 동시 3 · **Agent 질의(POST /agent/query)는 보내지 않음**. 합계 89회(부산 30 · 인제 30 · 영천 29), 모두 HTTP 200(성공 76 · 0건 8 · 부분 성공 5).
- 이 밖에 설계용 사전 점검 7회를 따로 보냈다(부산 2 · 인제 3 · 영천 2). 분류 이름·총건수 확인과 «산사태» 재난유형 확인용이며 JSON에는 넣지 않았다.
- 미리보기 5건(RISK_AREA·RISK_FACILITY·FLOOD_TRACE·SIMILAR_EVENT·PLAN)은 앱 `preview.ts` 와 같은 요청이다. 「자동 조회 데이터」로 먼저 뜨는 것과 같다.
- ms 값은 하네스 왕복 시간(동시 3 상태)이고, 괄호 안은 서버 `elapsed_ms`.
- 「10-27 녹화」는 `app/harness/recordings/data_2026-10-27T15-53-38-514Z.json` 이다. 같은 기준 시각이고 Data API는 같은 요청에 같은 결과를 낸다. HZ-1536·UP-609·SL-2611000001 상세는 여기서 인용했다.
- 「에이전트 DB」라고 적은 것은 지난 녹화(`cq_2026-10-27T16-29-27-437Z`, `regional_2026-10-27T17-46-51-490Z`)의 답 글에서 본 것뿐이다. 데이터 API 결과와 구분한다.

## 6. 시연 설계에 주는 뜻(조사에서 바로 나오는 것만)

1. **쪽 번호 근거는 사건에만 있다.** «근거 문서와 쪽»을 보여 줄 질문은 사건을 축으로 잡는다(부산 2020.7.23 → 2020 재해연보 p.153, 영천 2024.7 → 2024 재해연보 p.154, 힌남노 → 2022 재해연보 p.146). 위험지구·지하차도·급경사지의 근거는 「원천 표 · N행」으로 나온다.
2. **1초 안**에 나오는 것은 목록(위험·취약·침수흔적·유사사례·계획)이다. 상세(1.4~1.8초)·피해(1.8초)·근거(2~3초)는 1~3초가 걸린다. 지금 미리보기는 목록 5종만 부른다.
3. **조건입력**: T3Q-04는 재난유형·월·사건 이름 글자(키워드)·시도로 순위를 매긴다. 강우·특보 값은 쓰지 않는다(경고 «CONDITION_NOT_USED»). 조건 없이 지역+호우만 주면 점수 100인 사건이 여럿 나온다. 시점과 연도 키워드(예 «2020년»)를 주면 그 해 사건이 위로 온다(부산 7.23 사건 6위).
4. **빈 미리보기 주의**: 인제의 취약시설(지하차도) 미리보기와 영천의 침수흔적 미리보기는 «결과 없음»으로 뜬다.
5. 지역별 피해액, 당시 통제·대피 조치, 반지하·야영장·소하천 구역, 2006년 사건은 데이터 API로 나오지 않는다. 시연에서 다루려면 Agent 질의(1~4분)로만 가능하다. 미리 받아 둘(예열) 대상이며, 정답은 녹화로 확인해야 한다.
