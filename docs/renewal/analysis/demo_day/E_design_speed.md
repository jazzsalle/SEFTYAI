## 3. 질문 상세

공통 표기
- 조건 = 화면에서 그 질문에 붙여 보낼 query_context. 기준지역은 계정 기본값이다(부산광역시 SIDO · 강원특별자치도 인제군 SIGUNGU · 경상북도 영천시 SIGUNGU). 조건 칸 수는 조건 창에서 채울 칸 수다(D 3.2).
- 자동 조회 = 앱 `preview.ts` 5종 가운데 이 질문에 매길 것. 「앞 50」은 이번에 미리보기 본문 그대로 조회해 본 결과다(4.1).
- 근거: ◎ 문서+쪽(재해연보, 사건ID 목록 쪽 · 제목만) · ○ 원천 표·행(대상 상세 T3Q-15 의 관련 문서) · △ 계획 제목·ID 또는 집계 · × 없음.
- 대조값 = Data API 로 확인한 값이다(A · C · 이번 조회). 답 글을 맞춰 볼 때 쓴다. T3Q 확인 SQL 정답이라고 따로 적은 것만 정답이다.
- 원형 = T3Q 역량질문 변형(416 판정 · 시간 · SQL 회수는 변형 문서 채점 메모, B rows).
- 예상 시간은 추정이다. 같은 모양의 녹화값으로 잡았고, T3Q 처리 시간이 10초 계단(55 · 65 · 75 · 85 …)이라 «90초 안» = 85초 계단까지다.

## 5. 시험 방법(다음 단계에 넘길 것)

1. 7장의 JSON 46문(주 23 + 예비 23)을 지난 실측과 같은 동시 3으로 돈다. 주 질문을 먼저 돌린다. ● 14문은 다른 시각에 한 번 더 잰다(B 규칙 9 — 같은 모양도 시점에 따라 최대 131초 흔들렸다).
2. 판정 — T3Q `meta.elapsed_ms` 기준:
   - ≤ 85초(10초 계단 8번째까지) → 생방송 후보
   - 86~125초 → 예열하고 생방송에는 예비를 쓴다
   - ≥ 126초 → 예열 전용으로 두거나 예비로 바꾼다
   - 두 번 잰 값의 차이가 30초를 넘으면 생방송에서 뺀다
3. 자동 조회 시간도 같은 문항으로 잰다. 본문은 `preview.ts` 그대로다(RISK_* · FLOOD_TRACE · PLAN = 기준지역만, SIMILAR_EVENT = query_context 통째). 화면에 턴이 뜨는 시간 = 가장 느린 자동 조회다.
4. 하네스가 지금 빠뜨리는 것(D 6.1): `run.mjs` 의 `toRequest` 는 `period` · `detail.keywords` · `detail.conditions` 를 보내지 않는다. 특보 단계는 `weather_alerts` 에서만 만들고 `weather_warnings` 까지 만든다. 앱과 같은 요청이 되려면 이 JSON 의 `query_context_draft` 를 그대로 보내야 한다(`conditions` 원소에 `source_type: "MANUAL"` 만 덧붙임). `weather_warnings` 는 만들지 않는다(R6 — 특보는 기상청 실시간만).
5. 답 대조 — 질문별 «대조값»과 답 글의 숫자·이름을 맞춘다. 특히 BS-1 · BS-6 · YC-6 의 통제 기준 수심(5cm 와 15cm), IJ-2 의 토석류 249, IJ-1 의 D 17, YC-3 의 소하천 16, YC-5 의 단포 · 자천을 본다.

## 8. 요약

속도 우선안은 「재난담당자의 하루」 7장면에 주 질문 23문(부산 8 · 인제 8 · 영천 7)과 예비 23문, 모두 46문을 놓았다. 조건 입력 질의는 주 질문 11문(부산 4 · 인제 3 · 영천 4)이고 예비까지 18문이다. 주 질문 14문은 녹화에서 55~85초였던 모양을 따랐다. 대장 하나 · 거르기 하나이거나, 지구·사건·지점을 이름으로 집은 모양이다. 4문은 경계(85~130초), 5문(반지하 · 야영장 · 소하천구역 공간 분석과 재난문자 2)은 예열 전용이다. 자신 있는 점은 셋이다. 모든 주 질문이 0.2~1.0초 안에 Data API 자동 조회를 먼저 띄운다(대상이 앞 50건에 드는지 미리보기 본문으로 확인했다). 조건 질의는 «기간 + 연도 키워드»로 유사재난 자동 조회에서 그 사건을 위로 올린다(질문에 쓰는 6개 사건 가운데 4개는 5위 안, 나머지는 9위 · 14위). 그래서 사건 행에서 재해연보 쪽(p.146 · 148 · 153 · 154)으로 바로 잇는다. 기존 질문 모음 6문(녹화 55~85초)은 코드 변경 없이 바로 쓴다. 위험도 셋이다. 46문 가운데 40문은 이 모양 그대로는 아직 재지 않았고, 특히 침수흔적·문자 꼴은 녹화에서 90초 안이 하나도 없었다. 새 질문의 자동 조회 · 조건 프리셋 · 재해연보 쪽 화면 표시는 D ① · ② · ③ · ⑤ 승인 전에는 화면에 붙지 않는다. 반지하 · 야영장 · 소하천구역 · 인제 문자 · 인제 피해는 에이전트 DB만 답하므로 Data API 로 대조할 수 없다.
