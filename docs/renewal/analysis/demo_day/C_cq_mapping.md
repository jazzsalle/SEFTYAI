## 1. 결론

1. **원형은 T3Q 가 정답을 낸 것을 고른다.** 변형 70문은 Agent 416 기준 정답 56·부분 14·환각 0 이다. 우리 재실행은 자동 일치 40·부분 22다. 지역에 맞춰 바꿔도 **질문 모양**(데이터군 하나·범위·셈법을 글에 적음)은 그대로 둔다.
2. **빠른 길은 「자동 조회 데이터」다.** T3Q-05·30·04·10·12 는 0.25~0.9초, T3Q-15 상세는 건당 1.3~2.1초다(동시 8로 20건 약 4.5초, 60~70건 12~15초). Agent 는 55~277초(중앙 126초)이고 **10초 계단**으로 끝난다(§3).

## 5. 지역별 변형 후보 — 질문 글 초안

공통 규칙은 다섯 가지다.
- 질문 글만으로 완결되게 쓴다. T3Q 는 이전 대화를 Agent 에 넘기지 않는다(계약 §5.1).
- 데이터 출처와 범위(기간·「해제되지 않은」·구·하천)를 글에 적는다.
- 「지금·현재·예상·예측」은 쓰지 않는다.
- 조건(`query_context`)은 질문 범위와 같게 두고 값을 고정한다(§6).
- 「대조값」은 오늘 Data API 로 센 값이다. Agent 답을 볼 때 맞춰 보는 용도이고, T3Q 확인 SQL 정답은 아니다.

### 6.2 조건입력 질의를 빠르게 — 규칙

1. **조건이 Data API 결과를 바꾸는 것을 고른다.** 기간(→ T3Q-30·12), 기준지역(→ 전부), 분류(→ T3Q-05)가 그렇다. 특보 종류·단계는 Agent 글에만 반영되고 자동 조회는 그대로다. 앱 대응절차는 실제 발효 특보로 단계를 추천하고, 사용자가 단계를 바꿀 수 있다.
2. **조건 값을 고정한다.** 재사용 열쇠는 질문 글 + `question_source` + `query_context` + 특보 + 참조 + 대화다(`jobs.ts`).
   - `reference_time` 을 «지금»으로 두면 매번 새 질문이 된다.
   - 질문 모음 질문은 `SUGGEST` 로 나가므로 예열도 `SUGGEST` 로 해야 맞는다.
   - 시연 당일 그 지역에 특보가 발효 중이면 1시간 넘은 답은 다시 쓰지 않는다(D5). 상세는 D 문서 §3·§7.
3. **질문 범위 = 조건 범위.** Agent 는 조건으로 범위를 좁힌다(원문 §4 패턴 1, 녹화 P02-04-v1: «전체 문자» 질문을 호우로 좁힘). 범위가 넓은 질문은 글에 «재난유형 전체»를 적고 `disaster_types` 를 비운다.
4. **«해제되지 않은(지정 중)»과 셈 단위를 글에 적는다**(패턴 2). 공간 질문은 거리(50·100·200m)를 적는다(패턴 3).
5. **지금 앱·하네스에 빠진 것**:
   - 앱 자동 조회는 침수흔적에 `period`·`flood_year` 를 넘기지 않는다.
   - 시험 러너 `run.mjs` 의 `toRequest` 는 `period` 를 넘기지 않는다.
   - 둘 다 사용자 승인 뒤 고칠 것이다(D 문서 §5·§6).

## 9. 행동매뉴얼 질문(QQ-03) — 녹화 3건

`quick_query_id: QQ-03` 으로 보낸 것은 regional 녹화의 BR-04 3건뿐이다(cq 70문에는 없음). T3Q 는 `QQ-03` 이거나 질문에 «대응절차»·«행동매뉴얼»이 들어가면 매뉴얼 칸을 붙인다(계약 §5.1).

| 지역 | 상태 · 시간 | 매뉴얼 칸 | refs · 근거 | 답 글 첫 판단 | T3Q 자료·조건과 맞춰 본 것 |
|---|---|---|---|---|---|
| 부산 | SUCCESS · 109초 | `data_gaps: manual NOT_IN_SOURCE` · `manual null` · `action_items []` | 0 · 0 | «현재 단계: 호우경보 발효에 따른 … 비상 2단계» | 보낸 조건은 지역·호우뿐이고 특보는 없었다 → **발효 특보를 가정**했다. «(출처: 행정안전부 풍수해 재난위기관리 표준매뉴얼 및 지자체 풍수해 현장조치 행동매뉴얼)»이라고 적었으나 T3Q 원천에 매뉴얼은 없다 |
| 인제 | SUCCESS · 109초 | 같음 | 0 · 0 | «현재 대응 단계: 평시 / 관심(Blue)» | 도구 이름 `kma-forecast:get_hourly_forecast`·`hrfco-flood:get_flood_forecast_alerts` 와 10/29 강수 예보를 썼다 → **실시간·예보** |
| 영천 | SUCCESS · 137초 | 같음 | 0 · 0 | «현재 대응 단계: 관심(평시 상황관리)» | 동네예보, «금호강 영동교 수위 1.50m»·«영천댐 저수위 146.15m»(실시간). «금호지하차도»라고 적었으나 T3Q 의 영천 지하차도는 금노·영천지하차도다. «D등급 급경사지(고경면 오룡리 등)»라고 적었으나 T3Q D등급은 당지지구(화산면)·치산지구(신녕면)다 |

세 답에 공통인 점은 다음과 같다.
- `context_used` 는 고정 빈 값이고, `limitations` 는 고정 «유사사례는 예측·위험판단이 아닌 참고 정보»다.
- 답 글은 「단계별 조치」를 일반 지식으로 쓴다. 매뉴얼 쪽 번호는 하나도 없다.

**판단**: 사용자 조건(근거 문서·쪽, 실시간·예측 제외)을 셋 다 못 맞춘다.
- 시연의 「매뉴얼」 장면은 앱 대응절차(지역 매뉴얼 원문 단계·조치·쪽 번호, 즉시 표시)로 보인다.
- BR-04 를 기본 브리핑에서 뺄지는 사용자가 결정한다(요구사항 원문 문항).
- T3Q 답은 가공하지 않는 원칙이므로, 쓴다면 «T3Q 원천에 매뉴얼 없음» 표시가 그대로 보이는 사례로만 쓴다.
