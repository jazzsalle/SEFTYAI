# 업무흐름 및 서비스 시나리오

작성 2026-10-28 · 대상: 지자체(부산·인제·영천), 정부기관(행안부), 운영자

## 1. 업무 흐름 (풍수해 단계 × 서비스 기능)

| 단계 | 지자체 담당자가 하는 일 | 서비스 기능 |
|---|---|---|
| 평시 | 관내 위험·취약지역 파악, 과거 피해 사례 검토 | 지역 질문 라이브러리(업무단계 "평시"), 브리핑 세트, 자동 조회 데이터 카드, 지도 refs |
| 특보 발효 | 특보 확인 → 관내 위험지역 우선 점검 → 대응 단계 판단 | 특보 바·[특보로 질문], AI 모드 상황 점검, 대응 단계 바(SOP 추천 단계) |
| 비상 대응 | 단계별 조치, 유관기관 전파 | 대응절차 탭(행동카드·체크), 상황전파(연락망 → 발송·결과) |
| 복구·사후 | 피해·복구 사례 비교, 이력 정리 | 유사사례 질문, 대화·체크·발송 이력 |

정부기관: 전국 또는 시도를 기준으로 같은 질의 기능을 쓴다. 대응절차·발송 기능은 없고 연락망은 조회만 한다.
운영자: 작업 현황·예열·추적로그·계정 관리를 맡는다.

## 2. 서비스 시나리오

### S1. 아침 브리핑 (평시, 부산 담당자)
1. `bs_safety01`로 로그인 → 기준지역 부산광역시, 특보 바 "발효 특보 없음 · 기상청 · 갱신 08:40".
2. 시작 화면의 [브리핑 시작] → 내 브리핑 세트 4문항이 **동시에** 제출되고, 좌측 질문 큐에 4건이 진행 중으로 뜬다.
3. 1~2초 뒤 각 턴에 "자동 조회 데이터" 카드가 먼저 뜬다(위험지구 목록, 침수흔적 등 T3Q Data API 원응답).
4. 80~130초 사이에 에이전트 답이 완료순으로 도착한다. 큐 배지를 누르면 해당 답으로 이동한다. 운영자가 예열해 두었으면 즉시 표시되고 "08:10 생성" 라벨이 붙는다.
5. 답 안의 칩(예: [초량](#ref:r3))을 누르면 지도에서 강조된다.

### S2. 특보 발효 (인제 담당자)
1. 특보 바 "강원 인제 호우주의보 발효(10:00)" → [특보로 질문] 메뉴의 정의된 특보 질문을 고른다.
2. 질의에 `weather_warnings`(기상청 원문)가 붙어 큐에 들어간다. 매핑된 Data API(급경사지·위험지구)가 먼저 표시된다.
3. 대응 단계 바가 매뉴얼 근거와 함께 추천 단계를 표시하고, 담당자가 단계를 확정한다.
4. 대응절차 탭에서 조치를 체크하고, [상황전파]로 연락망 그룹에 발송한다(보존 기능).

### S3. AI 모드 (영천 담당자)
1. 헤더 [AI 모드] 켜기 → 즉시 1회 점검 질의(`AI_MODE`). 이후 탭이 열려 있으면 10분마다 점검한다.
2. 전광판 오버레이에 마지막 점검 답(무가공), 점검 시각, 다음 점검 예정을 표시한다.
3. 특보가 바뀌면 즉시 재점검한다. 이력은 `sa_ai_checks`에 남는다.

### S4. 자유 질문 여러 개 + 이어서 묻기
1. 입력창에 질문 A를 보내고, 기다리지 않고 질문 B·C를 연달아 보낸다(계정 동시 4건까지, 초과분은 대기열).
2. 완료순으로 답이 도착한다. A의 답에서 칩 2개를 고른 뒤 [이어서 묻기] → 접두 문맥이 붙은 질문이 전송된다. 말풍선 아래 "실제 전송 질문 보기"에서 원문 전체를 확인할 수 있다.

### S5. 조건 시나리오 질의 (사용자 입력 조건)
1. [재난상황 조건]에서 재난유형 호우, 기준시각, 1시간 강우 60mm 같은 조건을 직접 입력한다.
2. 조건은 `query_context.detail.conditions`로 그대로 전송되고, 화면에는 "사용자 입력 조건" 배지가 붙는다. 실시간 특보가 아님을 명시한다.

### S6. 정부기관 전국 질의
`mois_dsd01` → 기준지역 전국 또는 시도. 지역 질문 라이브러리는 3개 지자체 탭으로 열람한다.

### S7. 운영자
`/admin`: T3Q 연결 상태, 진행 중 작업, 강제 취소, [브리핑 예열], 추적로그, 계정 잠금 해제, 답변 평가 목록, 응답 시간 통계.

### S8. 오류·예외
| 상황 | 화면 |
|---|---|
| T3Q 연결 불가 | 상단 배너. 새 질의 접수 보류(QUEUED). 이력 조회는 가능 |
| 작업 유실(LOST) | "서버 재시작으로 작업이 유실되었습니다 · 다시 질의". 90초 이내면 1회 자동 재제출 |
| 10분 경과 | "계속 기다릴까요? / 취소" |
| 15분 경과 | TIMEOUT. T3Q 취소 |
| DATA_NOT_AVAILABLE | data_gaps 사유를 그대로 표시 |
| 세션 만료(30분 유휴) | 로그인 화면. 진행 중 작업은 재로그인 후 큐에서 복원 |

## 3. 11/5 중간보고 시연 흐름(안)
1. 로그인(부산) → 예열된 브리핑 세트 즉시 표시 → 칩 → 지도.
2. 자유 질문 2개 동시 제출 → 큐에서 완료순 확인(실시간 대기 시연).
3. 인제로 전환 → 급경사지 지역 질문 → 자동 조회 데이터 → 답 → 지도(급경사지 선형).
4. 영천 → 과거 호우 피해 사례 → 이어서 묻기.
5. 특보 바·AI 모드(실제 특보가 있으면 발효 특보로, 없으면 "특보 없음" 평시 점검).
6. 대응절차·상황전파(보존 기능) 짧게.
7. 운영자 화면: 응답 시간 통계, 원응답 검증(무가공 확인).
