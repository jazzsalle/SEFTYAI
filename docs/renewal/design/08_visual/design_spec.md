## 0. 판단 기준

| 원칙 | 이번 설계에서 지킨 방법 |
|---|---|

| 데이터 조회 값은 받은 그대로 | 값은 그대로, 표시 형식만(§0.2). 유엔이가 센 수는 모두 「유엔이가 센 값」을 글자 그대로 붙인다. 센 수 자체를 줄였다(등급별 4건·답변 대상 반복·칸 막대 삭제). |
| 화면 글자는 한국어 | 필드 이름·상태·코드는 사전으로 한국어. **툴팁에도 영문 키를 쓰지 않는다.** 제공처 알림 원문(영문 키·내부 이름·파이썬 목록이 섞임)은 화면에 두지 않고, 코드별 한국어 이름 + 고정 문장(사전)만 보인다. 원문은 운영관리 · 추적로그. 사전에 없는 키와 판·코드 키는 화면에 두지 않는다(§0.2). |
| 빨강 금지 | 그림은 파랑·청록·초록(전 쌍 검증 통과), 주의는 노랑, 경보 상태도 진한 노랑. 지도 표식도 같은 규칙(§0.3). |
| T3Q 시험 화면 요소를 따르지 않음(소유자: 「요인쓰임 같은 건 따라하지 말자 · 참고만 하고 독자 구성」) | 쓰지 않은 것: 「요인 쓰임 %」(어디에도 없음), 제목 옆 「정상」·「일부 제공」 배지, 조회 ms 표시, 요인 표(요인·현재·과거·일치도·기여 열), 순위·사건·기간·지역·유사도 열의 목록 표, 큰 유사도 숫자 칸(「96.7 / 100 전체 1위」), 기본 정보 행 나열, 두 칸 고정 배치. 대신: 사건·피해 요약이 먼저인 목록 줄, 막대 조각에 매단 요인 묶음, 범위 문구, 우리 지역 기록 표. |

### 0.2 공통 표기 규칙

| 규칙 | 예 | 비고 |
|---|---|---|
| 천 단위 쉼표는 **측정량 키만** — 금액(`*_krw`), 건수(`record_count`·`item_count`·`total_count`), 면적(`area_m2`), 명(`displaced`·`dead`·`missing`·`injured`·`persons`). 소수부는 받은 자릿수 그대로 | `1037156500000` → `1,037,156,500,000` · `46.6667` 그대로 | `toLocaleString` 은 소수 3자리로 반올림하므로 쓰지 않음 |
| 쉼표 금지 — 연도(`*_year`, `flood_year`, `disaster_year`, `built_year`), 번호·코드(`*_id`, `admin_code`, `row_no`, `disaster_id`, `designation_no`), 날짜 문자열. **모르는 숫자 키는 받은 그대로**(쉼표 없음) | 준공연도 `1995`, 재해 번호 `227` | 키 목록은 `labels.ts` `COMMA_KEYS` |
| 날짜 시각 | `2020-08-08T15:20:00` → `2020-08-08 15:20`, 시작=종료면 한 번 | 승인 G1 |
| 빈 값 | `null` → `—` + 툴팁 「제공되지 않았습니다」 | |
| 정보 부족(`data_gaps`) | 영향 받는 자리 옆에만 ⚠ + 「끝 이름(소속) — 원자료에 없음」. 경로에 「·」를 쓰지 않는다 | 예 `강우(유사도 요인)`, `피해(유사도 요인군)`, `각 항목의 최대 침수심(m)`, 이재민 칸 아래 `사망·실종·부상 원자료에 없음` |

| 시각 이름 | `질문 기준시각`(담당자가 정함) · `답변 시각`(답 `meta.base_time`) · `자료 기준일`(데이터 조회 `meta.base_time` 날짜) | 「기준」을 한 가지 뜻으로만 |

| 식별자·코드 | 기본 화면에 두지 않는다 → 툴팁 또는 「원본 항목 전체 보기」. 응답 번호는 답 바닥 「문의용 응답 번호 [복사]」 | 사건 번호·대상 번호(「ID」 대신) |

| 화면에 두지 않는 키 | `similarity.coverage`, `algorithm_version`, `scale`(문자열), `schema_version`, `request_id`, `correlation_id`, `meta.source`, `weights.weight_stage`, 사전에 없는 키 | 「받은 항목 더 보기」에도 없음. 사전에 없는 키는 추적로그에 남겨 관리자가 사전에 추가 |

| 오류 | 노랑 알림 `사건 상세를 불러오지 못했습니다. 잠시 후 다시 조회하세요.` + `다시 조회` | — |
| 사건 요약 받는 중 | 목록 줄 둘째 줄 회색 줄 + `사건 상세에서 받는 중`(1위 카드) | 시안 A 1~10위 |
| 섹션 없음 | `available_sections` false 면 `이 사건은 {섹션}을 제공하지 않습니다.` | 보고서·위성영상 |

### A.5 접근성
- 막대·러그는 같은 값이 표에 있다(표로 보기, 우리 지역 기록 표, 전체 기록 표). 막대 조각은 키보드 초점 + `aria-label`(요인군·점수·비율), 누르면 그 묶음 펼침(`aria-expanded`). 러그 회색 선 100개는 초점을 주지 않고 우리 지역 기록만 초점.
- 1위·선택·정보 부족은 색 외에 글자(`유사도 1위`, `상세 열림`, ⚠ + 문구)로도.
- 툴팁 글자는 `textContent` 로 넣는다.

### C.5 접근성
머리 줄은 `role=toolbar`, 붙어 있어도 초점 순서는 머리 → 대조 줄 → 한계 → 먼저 확인 → 답 글. 목차 링크는 제목 `id` 로 이동하고 그 제목에 초점. 대상 링크는 버튼(`aria-pressed`), 이름은 링크 글자 그대로. 표 상자는 `role=region` + `aria-label`(「표 n — 옆으로 스크롤」)·키보드 가로 스크롤. 찾기 결과 수는 `aria-live=polite`. 글자 크기 단계가 커지면 머리 줄은 두 줄로 줄바꿈(시안 C 상태 4).

현황판은 `role=list`, 칸은 링크: 읽기 문구 예 「1번 위험·취약지역, 완료, 약 1분 25초, 근거 문서 없음」. 답 도착은 `aria-live=polite` 로 한 번. 돌기는 움직임 줄이기 설정에서 멈춤. 빗금 없음. 상태는 글자+기호.

## 발견한 결함(바로 고칠 것)

1. **답 글 취소선 결함(R0)** — 1판에서 찾음. `Markdown.tsx` 15행 `REMARK_PLUGINS = [[remarkGfm, { singleTilde: false }]]` 로 고쳐진 것을 확인. 하네스 무가공 테스트에 물결표 두 개 문단이 들어 있는지 확인할 것.
2. **굵게 구분자 결함(신규 · R0 연관, 승인 G5)** — CommonMark 규칙상 닫는 `**` 앞이 문장부호이고 뒤가 한글이면(예 `…저지대)**입니다`, `…에서**'불안전'**으로`) 굵게가 되지 않아 **별표가 글자로 보인다.** 녹화 답 122건(중복 제외) 중 **78건, 332곳**(예: 시안 D 1번 답 첫 문장, 시안 C 상태 4 `**'불안전'**`). 시안은 앱과 같은 규칙으로 그려 그대로 보인다. 고침 후보: CJK 친화 구분자 규칙을 쓰는 remark 플러그인(예 `remark-cjk-friendly` — 개발에서 판·호환 확인) — 글자는 그대로, 굵게만 글쓴이 뜻대로. 제공처에도 생성 규칙 요청.
3. **정보 부족 경로의 영문·「·」 혼용** — `componentKo` 가 `items[]` 를 모르고 경로를 「·」로 잇는다 → `gapName` 규칙(§0.2)으로.
4. **제공처 문구 속 영문 코드·내부 이름**(`RAIN_1H`, `warning_level`, `152`, `T3Q-15/30`, 파이썬 목록) — 화면 비노출(G3)로 해결, 원문은 추적로그.
5. **툴팁의 영문 키** — `DataCard.tsx` 78행 `<th title={k}>` → 지운다.
6. **반려 요소 잔존** — `labels.ts` 32행 `coverage: "비교에 쓴 요인 비율"`(1판 때 「요인 쓰임」) → 지우고 표시 금지 키 목록으로.
7. **보고 단계 묶음 막대** — 표로(1판).
8. **첫 화면 예산 초과(신규)** — 앱 특보 줄 `min-height:50px`, 대응절차 줄 `46px` → 44·40px(§0.4). 그대로면 첫 제목이 12px 내려가 450px 선을 넘는다.
